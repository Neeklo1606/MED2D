# MEDFORM: ТЗ для программиста

Nov 19, 2026 · @neeklo

## Цель и рамки v1

Собрать интернет-магазин медицинской одежды MEDFORM на med.neeklo.ru, который работает в режиме заявок: покупатель собирает образ в конфигураторе, кладёт в корзину и оформляет заказ без онлайн-оплаты, менеджер получает заявку в Telegram и в админке.

- **Входит в v1:** все страницы, конфигуратор, каталог и карточки, корзина, оформление заявки, админка с полевым управлением контентом, заявки в Telegram, юридические страницы, cookies, SEO-основа, адаптив mobile-first.
- **Не входит в v1:** онлайн-оплата ЮKassa и доставка СДЭК. Заказчик подключит их примерно через месяц. Сейчас закладываем интерфейсы и флаги, интеграции делаем отдельным этапом.
- **Ассортимент:** около 10 товаров и 50 вариантов: халат, анорак, джоггеры, футболка, шапочка, докерка, сабо, шнурок, шопер, термокружка (под вопросом).
- **Домен:** сейчас med.neeklo.ru, закрыт от индексации. Потом переезд на домен заказчика сменой переменных окружения.
- **Подробная спецификация агента:** файл `prompts/MASTER_med-neeklo-ru.md` в папке проекта (критерии приёмки, модель данных, этапы).

## Стек и инфраструктура

| Слой | Решение |
| --- | --- |
| Фронт + сервер | Next.js (App Router), TypeScript strict, Node 22, pnpm |
| Стили | Tailwind CSS + CSS-переменные токенов из Figma |
| 3D | three.js через react-three-fiber + drei, модели GLB |
| Состояние | Zustand (конфигуратор, корзина с persist) |
| БД | PostgreSQL 16 + Drizzle ORM, миграции в репозитории |
| Медиа | Локальный volume + sharp (WebP/AVIF), отдача через Caddy |
| Уведомления | Telegram Bot API (webhook), SMTP |
| Инфраструктура | Docker Compose (app, postgres, caddy) на нашем VPS в РФ, GitHub Actions |

Запрещено: Supabase, n8n, Firebase, Google Analytics, Google Fonts с CDN, зарубежные сервисы, получающие персональные данные. Деньги храним в копейках (integer), суммы всегда пересчитываем на сервере.

Переменные: `APP_URL=https://med.neeklo.ru`, `INDEXING_ENABLED=false`, `PAYMENTS_PROVIDER=none`, `DELIVERY_PROVIDER=none`, `DATABASE_URL`, `TELEGRAM_BOT_TOKEN`, `TELEGRAM_WEBHOOK_SECRET`, `SMTP_*`.

## Страницы и механика покупки

Экран конфигуратора верстается по согласованному макету ([Figma, страница «Конфигуратор итог»](https://www.figma.com/design/9fKr0pDLkGKPchDhW34P8a/Medform?node-id=42-2)). Остальные страницы в макете не нарисованы: собираем в той же визуальной системе.

| Маршрут | Что на странице |
| --- | --- |
| `/` | Первый экран с УТП и кнопкой «Собрать образ», тизер конфигуратора, о бренде, покупателям кратко, контакты |
| `/catalog` | Конфигуратор по макету + сетка всех товаров с фильтрами |
| `/product/[slug]` | Галерея, цвет, размер, таблица размеров, состав, уход, производитель, сертификат, «Примерить» |
| `/cart` | Состав, смена размера и количества, удаление, итого |
| `/checkout` | Оформление заявки в одну колонку |
| `/order/[token]` | Номер заявки, состав, что дальше и в какой срок свяжутся |
| `/about`, `/buyers`, `/contacts` | О бренде; доставка, оплата, возврат, FAQ; контакты |
| `/legal/*` | Оферта, политика ПДн, согласие на ПДн, cookies, реквизиты |
| `/admin/*` | Админка (закрыта, noindex) |

Путь покупателя в v1:

1. Выбирает модель Ж или М, надевает вещи, меняет цвета, выбирает размеры.
2. «Добавить весь образ в корзину» или по одной вещи. Без размера добавить нельзя: поле подсвечивается.
3. В корзине правит состав. Корзина сохраняется между визитами, цены сверяются с сервером.
4. Оформление без регистрации: имя, телефон, email, город, адрес, комментарий (необязательно), отдельный чекбокс согласия на ПДн, ссылка на оферту. Кнопка «Отправить заявку».
5. Сервер проверяет данные, пересчитывает сумму, сохраняет заявку (статус `new`, время согласия, версия оферты), ставит уведомления в очередь.
6. Покупатель видит страницу успеха и письмо, менеджер получает сообщение в Telegram и заявку в админке.

Статусы заявки: `new` → `in_progress` → `contacted` → `confirmed` → `shipped` → `completed`, плюс `cancelled`. Для онлайн-оплаты потом добавятся `awaiting_payment`, `paid`, `refunded`.

## Конфигуратор и 3D-заготовки

Конфигуратор собираем в 3D на готовых заготовках: 16 GLB-файлов, манекены Ж и М и 7 вещей на каждый. Пропорции условные, задача заготовок: собрать и отладить всю логику до того, как 3D-художник сдаст финальные модели. Финальные файлы заменяют заготовки под теми же именами, без правок кода.

- Покрутить и перекрасить: [MEDFORM: 3D-заготовки конфигуратора](https://claude.ai/artifact/1YPa89eEbBJwQwK3TF6yw9). Это же рабочий пример логики слотов на three.js.
- Файлы: `medform-shop/3d/models/` в папке проекта, там же `manifest.json` (слот, треугольники, габариты) и генератор `gen.py`.

| Файл (`_f` / `_m`) | Слот | Товар |
| --- | --- | --- |
| `mannequin` | base | Манекен (не перекрашивается) |
| `top_anorak` | top | Рубашка-анорак |
| `top_tshirt` | top | Футболка оверсайз |
| `bottom_joggers` | bottom | Брюки-джоггеры |
| `coat_halat` | coat | Халат, надевается поверх top |
| `head_cap` | head | Шапочка |
| `head_dokerka` | head | Докерка |
| `feet_sabo` | feet | Сабо |

Правила конфигуратора:

- Одна вещь на слот, новая вещь в слоте заменяет старую; «Снять всё» очищает слоты, пол модели сохраняется.
- Цвет меняется сменой `material.color` у материала `fabric`, отдельные файлы под каждый цвет не нужны. Hex цветов берём из админки.
- Вращение пальцем и мышью, зум кнопками «+ −» и щипком, сброс камеры.
- Образ кодируется в URL и восстанавливается по ссылке.
- Без WebGL или на слабом телефоне включается 2D-режим по фото (как в макете). Рендер спрятан за интерфейсом `LookRenderer` с двумя реализациями: `three` и `photo`.
- 3D грузится лениво (dynamic import), `frameloop="demand"`, dpr не больше 2. Бюджет: стартовая сцена до 3 МБ, все модели до 12 МБ, 30+ FPS на среднем Android.
- Вопрос заказчику: на сайте в итоге 3D или фото-модель из макета (слои вещей на фото). До ответа делаем оба рендера за одним интерфейсом.

## Админка, полевое управление, Telegram

Менеджер должен без разработчика менять любой текст, цену и фото и обрабатывать заявку с телефона.

**Полевое управление контентом**

- Реестр полей в коде (`src/content/registry.ts`): страница, секция, ключ, тип (text, richtext, image, link, number, boolean, list), подпись, подсказка, значение по умолчанию, лимит символов.
- Админка строит формы из реестра автоматически. На сайте нет захардкоженных текстов, кроме системных ошибок.
- Изменение видно на сайте не позже чем через 60 секунд (revalidate), есть история изменений и «Вернуть по умолчанию».

**Разделы админки**

| Раздел | Что там |
| --- | --- |
| Дашборд | Новые заявки, сумма за неделю, товары без цены, фото или 3D-модели |
| Заявки | Список с фильтрами, карточка, смена статуса, заметка менеджера, экспорт CSV |
| Каталог | Товары, варианты таблицей (цена, остаток, вес, габариты, SKU), фото, GLB-модели, цвета (hex), размерные сетки, сертификаты, импорт CSV |
| Контент | Поля всех страниц по реестру |
| Настройки | Реквизиты, контакты, условия доставки и возврата, Telegram chat id + тестовое сообщение, флаги оплаты и доставки, индексация |
| Пользователи | Роли owner и manager, журнал действий |

Вход: email + пароль (argon2) + одноразовый код, ограничение попыток, `noindex`.

**Заявки в Telegram**

- Заявка сначала сохраняется в БД, потом уходит через очередь `notification_outbox` с повторами: сбой Telegram не теряет заявку.
- Сообщение: номер MF-00001, сумма, состав (товар, цвет, размер, кол-во), имя, город, комментарий, ссылка в админку. Телефон и email в чат не уходят по умолчанию (флаг в настройках).
- Кнопки «Взять в работу», «Связались», «Отменить» меняют статус в админке, бот редактирует сообщение с именем менеджера.
- Webhook защищён секретом `X-Telegram-Bot-Api-Secret-Token`. Дубль заявки на email менеджеру, письмо покупателю «Заявка принята».
- Формы «Задать вопрос» и «Подобрать размер» идут тем же путём.

| Адаптив | Проверка на 360, 375, 390, 414, 768, 1280, 1440 px, тач-цели от 44 px, реальные iOS Safari и Android Chrome |
| Безопасность | HTTPS + HSTS, заголовки безопасности, страница заказа только по токену, honeypot и лимит частоты на формах, секреты только в env |

| Бэкапы | Ежедневный pg\_dump + архив media, ротация 14 дней, проверенное восстановление |

## Этапы и приёмка

Каждый этап закрывается показом на стейдже и отчётом: что сделано, как проверено, что на заглушке.

| Этап | Результат | Как принимаем |
| --- | --- | --- |
| 1. Каркас | Репозиторий, схема БД, сиды каталога, Docker, CI, стейдж med.neeklo.ru | `docker compose up` поднимает сайт, CI зелёный |
| 2. Вёрстка | Дизайн-система из Figma, все страницы, адаптив | Скриншоты 375 и 1440 px всех страниц |
| 3. Конфигуратор | 3D на заготовках, слоты, цвета, ссылка на образ, фото-фолбэк | Образ собирается на реальном телефоне, видео |
| 4. Каталог и корзина | Карточки, таблица размеров, корзина, оформление заявки | e2e: образ → корзина → заявка в БД |
| 5. Telegram | Бот, очередь с повторами, кнопки статусов, письма | Тестовая заявка приходит, статус меняется кнопкой |
| 6. Админка | Полевое управление, каталог, заявки, настройки, роли | Заголовок и цена из админки видны на сайте за минуту |
| 7. Юр, SEO, QA | Документы, cookies, метаданные, Lighthouse, кросс-браузер | Все обязательные требования выполнены |
| 8. Деплой | Прод на med.neeklo.ru, бэкапы, мониторинг, инструкция по админке | Смоук-тест на проде |

## Спецификация для 3D-художника

Финальные модели сдаются под теми же именами файлов и с теми же параметрами, что заготовки, чтобы замена не требовала правок кода.

| Параметр | Требование |
| --- | --- |
| Формат | glTF 2.0 бинарный (.glb), сжатие Draco или Meshopt, текстуры KTX2 |
| Единицы и оси | Метры, Y вверх, модель смотрит на +Z, стопы на Y = 0, центр по X = 0 |
| Манекены | Ж рост 1.68 м, М рост 1.80 м, одна поза (руки чуть в стороны), без лица или стилизованные |
| Одежда | Каждая вещь отдельным файлом, сидит на своём манекене (`_f` / `_m`) без просвечивания тела; халат не пересекается с анораком и футболкой |
| Материалы | Основная ткань: материал `fabric`, базовый цвет белый, цвет задаёт сайт. Фурнитура (кнопки, логотип) отдельным материалом `trim`, не перекрашивается |
| Текстуры | Нормали и AO складок и ткани до 2048 px, без цвета в albedo (иначе перекраска ломается) |
| Бюджет | Манекен до 30 тыс. треугольников, вещь до 20 тыс., файл вещи до 1.5 МБ с текстурами |
| Имена | Узел = имя файла без пола (`top_anorak`), файл = `top_anorak_f.glb` |
| Проверка | Модель открывается в просмотрщике заготовок и садится на манекен без сдвига |

Референсы для художника: фото финальных образцов с фабрики и описания из каталога (крой, карманы, воротники). До их получения на сайте работают заготовки.
