# Ночной план MEDFORM (22→23.11.2026): показ заказчику

Цель утра: https://med.neeklo.ru с реалистичным 3D-конфигуратором, быстрая загрузка, аккуратный UI на телефоне и
компьютере, пройденные критические тесты, короткая инструкция-отчёт.

## Критика плана (7 проходов)
1. **Figma недоступна** (CloudFront 403 из контейнера и через embed). «Как в Figma» = только токены, снятые раньше со скриншота мобильного макета. Не обещаем пиксель-в-пиксель, сверяем с `docs/design-tokens.md`, отмечаем в отчёте.
2. **Конфликты параллельной работы.** Агенты в отдельных worktree и ветках, у каждого своя зона файлов: «Скорость» — `ThreeRenderer` загрузка/кеш, `next.config.ts`, `tools/3d/optimize.mjs`; «Интерфейс» — `Configurator.tsx`, `src/shop`, `src/site`, стили; «QA» — только `tests/`. Модели (`public/3d`) трогает только ведущий. Слияние делает ведущий.
3. **Риск сломать стейдж.** Деплой только после `lint + typecheck + test + build` и e2e на прод-сборке; после деплоя проверка живого сайта (статус, загрузка моделей, консоль). Откат = пуш предыдущего коммита.
4. **Слабые телефоны.** 3D по умолчанию только при WebGL и памяти ≥ 2 ГБ, фото-режим остаётся; сжатие моделей и `dpr` ≤ 2; рендер по требованию (`frameloop="demand"`).
5. **Новые зависимости запрещены без согласования.** Сжатие — инструмент сборки через `npx @gltf-transform/cli` (в сайт не попадает); декодер meshopt уже есть в three/drei.
6. **Кеш и старые модели.** Имена файлов не меняются → добавляем `?v=<хэш файла>` из manifest и `Cache-Control: immutable`; service worker кеширует по версии.
7. **Реализм против ТЗ.** ТЗ просит «без лица или стилизованные», пользователь — реалистичных людей. Делаем реалистично, в отчёте отмечаем как вопрос заказчику.

## Порядок
1. Запуск агентов 2–4 параллельно; ведущий делает поток 1.
2. Слияние → проверки → деплой №1 (модели + скорость).
3. Слияние UI и тестов → проверки → деплой №2.
4. Повторный круг QA на живом сайте → исправления → деплой №3 → отчёт.
